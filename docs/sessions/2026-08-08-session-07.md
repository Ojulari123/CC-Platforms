## What was built

### Week 4 close-out — real notification (Route B, both services)
- **Identity: OAuth2 client-credentials service auth.** New `service_clients` table
  (migration `0008`), `POST /oauth/token` (client-credentials → short-lived **scoped**
  service JWT, `token_type:"service"`, distinct from user tokens so a service can never
  masquerade as a user), and `POST /internal/users/emails` (scope `users:read:email`) to
  resolve `user_id → email`. The `pulse` client is seeded from `PULSE_CLIENT_SECRET`;
  seeding **never re-activates a manually-revoked client** (revocation persists across
  restarts). (`app/security/jwt.py`, `app/services/service_clients.py`,
  `app/routes/oauth.py`, `app/routes/internal.py`.)
- **Pulse: identity client + real send.** `app/services/identity_client.py` mints/caches a
  service token and resolves approver emails; `notify_report_ready` now actually sends via
  the existing Brevo `send()` — still best-effort (any failure logs and never blocks the
  submit). Config: `IDENTITY_API_URL`, `PULSE_SERVICE_CLIENT_ID/SECRET`.

### Identity — accounts
- **Self-signup — `POST /auth/signup`** (public, rate-limited). Domain-gated by
  `SIGNUP_ALLOWED_DOMAINS` (**empty = allow any domain**, the current dev setting). Creates
  a plain, **membership-less, non-admin** user and logs them in. Register stays
  bootstrap-only.
- **Admin placement — `POST /departments/{dept_id}/members`** (dept admin). Adds an existing
  user to a department with a role/team — also the clean way to place a signed-up user or
  add someone to a second department without re-inviting.
- **App-wide directory — `GET /platform/users`** (platform admin). Paginated, `q` search,
  `is_active` filter; shows users in any department **or none**.

### Forge — product 2 (new service, `services/forge/`)
- **Skeleton (Phase 0).** Bootable FastAPI, local JWKS token verification via `crescent_core`
  (never calls identity, never touches its DB), own `forge` DB, Alembic, health route, port
  **8003**, docker-compose service + `forge`/`forge-migrations` CI jobs.
- **Dataset backend (Phase 2).** `Dataset` model + migration `0001`; `POST /datasets` (CSV
  upload → validate → store), `GET /datasets` (own + samples), `GET /datasets/{id}`,
  `GET /datasets/{id}/preview` (first N rows, capped at 500), `DELETE /datasets/{id}` (owner
  only; samples 403). CSV **content stored in the DB** (small learning datasets, no volume
  needed). Two **sample datasets** seed on startup so a new user is never empty.
- **Frontend foundation (Phase 1).** Nuxt 3 + TypeScript + Tailwind + TanStack Query + Zod at
  `services/forge/frontend/` (npm). Login → identity `/auth/login`, token store with
  refresh-on-401, route guard, and a protected page listing datasets. `forge-frontend` CI job.
- **Dataset UI (Phase 3).** CSV upload form, list with links, a preview page (columns + rows
  + truncation note), and confirm-guarded delete (hidden for samples).

## Decisions

- **Service-to-service auth = scoped, minted service tokens (OAuth2 client-credentials),
  not a static shared key.** Reuses the existing RS256/JWKS crypto, is revocable, carries a
  least-privilege scope, and is the pattern Forge will reuse — a static key would multiply
  per service pair.
- **Signup allow-list is a config toggle; empty = allow all.** Frictionless for dev, lockable
  to `cyphercrescent.com` later with one `.env` change (tracked). Email verification
  deliberately deferred — the domain gate is the v1 guard.
- **Forge stores CSV content in the DB, not on disk.** Simplest self-contained option for
  small datasets; sample datasets exist purely for first-run onboarding.
- **Frontend: per-product Nuxt app** under `services/forge/frontend/`; the auth composable
  lives in-app for now and extracts to `packages/ui` when Pulse gets a frontend (YAGNI).
- **Teams are identity org structure, latent by design.** Pulse is repo-centric on purpose
  (approvals via a repo's lead/deputy, not team managers). Teams work and ride in tokens but
  no product consumes them yet — capability, not a bug. Fixed the `require_team_manager`
  docstring that wrongly claimed Pulse routes approvals through team managers.

## How it was verified

- **Route B end-to-end (real):** identity run as a live uvicorn subprocess, Pulse's real
  `identity_client` driven against it over HTTP — mints a service token, resolves both
  approver emails, and attempts a Brevo send (only the send transport stubbed). Wrong secret
  → 401 swallowed; a user token → rejected at `/internal/users/emails`.
- **Test suites (all green):** identity **254**, Pulse **163**, Forge backend **32** (incl. a
  genuine lifespan-boot seeding test). Forge frontend `npm run build` passes and the server
  boots (routes resolve 200).
- **Migrations on real Postgres:** identity `0008` and Forge `0001`+`0002` each apply → empty
  drift-check → downgrade round-trip cleanly.
- **NOT verified:** the live Forge login→datasets→upload flow (needs the running stack + a
  login; the auth step can't be self-verified). To check: `docker compose up`, then
  `cd services/forge/frontend && npm run dev`, log in, confirm the sample datasets appear.

## Known limitations

- **Backend audit — all findings FIXED (this session).** The signup-bootstrap bug is closed:
  `register` now shuts only once a *platform admin* exists, so a prior non-admin signup can't
  brick it. Robustness cluster fixed too — chunked upload with an early 413 (no full-body
  buffering); `list_datasets` no longer hydrates CSV content (SQL LIMIT/OFFSET + deferred
  column); sample double-seed closed with a partial unique index `uq_sample_name` (Forge
  migration `0002`) + savepoint-guarded seeding; malformed CSV → 400; and `add_member`
  duplicate race → 409 (was 500). One accepted nuance: a NUL byte in a cell isn't a
  `csv.Error` in this stack, so it's stored as data rather than rejected — harmless.
- **Signup allow-list is wide open** (`SIGNUP_ALLOWED_DOMAINS=""`) — intended for dev; must be
  locked before any non-local deploy (tracked as a follow-up task).
- **GitHub OAuth not configured locally** (`GITHUB_CLIENT_ID/SECRET` blank) → live Pulse sync
  is blocked until an OAuth App is set up.
- **CI:** the `forge-frontend` job runs `npm ci`, so `services/forge/frontend/package-lock.json`
  must be committed or that job fails.

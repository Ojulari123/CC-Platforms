## What I did

### 1. Quick wins first
- **Rate limiting** (`slowapi`, ported from FindYourCribb): 5/min register,
  10/min login, 30/min refresh, 5/min change-password. Per-IP, in-memory.
  `RATE_LIMIT_ENABLED` lets the test suite hammer `/auth/*` freely; the
  dedicated rate-limit tests flip the limiter on for themselves and reset it
  after, so limits can't leak between tests.
- **CI now tests `packages/core`** — it had never run in CI at all.
- Committed two fixes left uncommitted from session 02: `require_role` chaining,
  and `.dockerignore` excluding `keys/` so the JWT signing key can't be baked
  into the identity image.

### 2. org → department (full rename)
`org_name` on registration was confusing, and rightly so: CypherCrescent is the
only organisation this platform will ever serve, so the thing a person actually
belongs to is a **department**. Renamed everywhere — tables, models, the JWT
claim, `packages/core`, tests, docs. Migration `0003` renames in place
(`ALTER TABLE … RENAME`) rather than drop/recreate, so existing rows survived.

Worth remembering: **macOS `sed` doesn't support `\b`**, so the first pass
silently changed only the prose and none of the identifiers. `perl -pi -e` after
that.

### 3. The bug that caused the restructure
While removing `dept_id` from URLs (a person's department can come from their
token — why type it?), I tested what happens to someone in **two** departments:

> Bob is **admin of his own department** and an **engineer in Alice's**.
> `/me` and `/dept` both silently resolved to Alice's — an arbitrary first row.
> `PATCH /dept` returned **403**, and Bob was locked out of the department he
> actually ran, with no way to reach it.

The convenience of a short URL had quietly baked in "everyone is in exactly one
department". So the restructure:

- **Every department endpoint names its department**: `/departments/{id}/…`.
  Permission is checked against *that* department, so a person can be an admin
  in one and an engineer in another with no bleed.
- **Tokens carry every membership**, not one:
  `"memberships": [{dept_id, team_id, role}, …]` plus `is_platform_admin`.
  A single `dept_id` claim would have re-created the same bug *inside a signed
  token other services trust*. `packages/core` got `role_in(dept_id)`,
  `is_member_of`, `dept_ids`, and `require_dept_role` reading `dept_id` from the
  path.
- **`/me` returns all memberships** instead of one arbitrary "active" one.
- **Platform admins** (`is_platform_admin`, migration `0004`): nobody could
  create a second department — they only appeared as a side effect of someone
  registering. Plus `PUT/DELETE /platform/admins/{id}` to appoint others, with a
  can't-remove-the-last-one guard.
- **Registration is bootstrap-only**: first user creates the platform admin and
  the first department; after that it's 403 and everyone joins by invite.

### 4. Teams got their own surface
Team membership was a side effect of `PATCH …/members/{id}` — there was no way
to list a team's people, and no team-scoped add/remove. Now:
`POST/GET/PATCH/DELETE …/teams`, `GET …/teams/{id}/members`,
`PUT/DELETE …/teams/{id}/members/{user}`. Plus a flat `GET /teams` across
departments, because hunting for a dept id just to look around was silly.

### 5. Named leads, and then decoupling them
`Team.manager_user_id` (migration `0005`) — "who runs this team" needs one
answer, and Pulse routes every weekly report to it. The lead may manage their
own team's roster; they still can't create/rename/delete teams, invite, or
change roles.

Then the question *"what if the manager isn't in that team yet?"* exposed two
real bugs:
- appointing a lead to a second team left the **first team pointing at them**
  with an empty roster — exactly the contradiction the design was meant to
  prevent;
- `GET …/teams/{id}` always returned `manager_name: null`, because that route
  handed back the raw ORM row.

Rather than patch the first, we removed its cause: **leading a team and being on
it are now separate facts**. Appointing moves nobody, so nothing can be
stranded. Bonus, and the answer to "what if my boss wants one manager over many
teams": that already works — `manager_user_id` has no uniqueness constraint, so
it's zero migration if asked for.

### 6. Department heads, and a handover guard
"Who runs Engineering?" had no answer in the data — only the *set* of people
with `role: admin`. `Department.head_user_id` (migration `0006`), appointed by a
platform admin, who must already hold admin there.

And removing someone in charge no longer happens quietly: it returns **409**
naming what would be left leaderless, and you either pass
`?replacement_user_id=` or `?allow_unled=true`.

### 7. Invites, and Brevo
- Invites already carried an optional `team_id` — you could hire someone
  straight onto Platform — but **neither the email nor the accept page ever said
  so**. Both now name the team.
- `GET /departments/{id}/invites`, `DELETE …/invites/{id}`, and public
  `GET /invites/preview?token=` so the accept page can show "Join Engineering as
  engineer" and know whether to ask for a password.
- `app/services/email.py` logs Brevo's response body on failure — without it
  every failure looked identical. That's what made the sender-validation problem
  findable. **Brevo is now sending for real.**

### 8. Also fixed
- `POST /auth/logout-all` — `revoke_all_for_user` had existed since session 02
  with **no route**, so "log out everywhere" was unreachable. A real bug, not a
  gap.
- `PATCH /me` for name/avatar.
- Adminer added to compose for browsing the local database in a browser.

## Things that cost time (worth not repeating)

1. **A 401 "Invalid token" I couldn't explain.** Reproduced it: Swagger's
   *Authorize* box already adds `Bearer `, so pasting `Bearer eyJ…` sends it
   twice and the token doesn't parse. Paste only the raw token. (A wrong
   department gives a *different* message — that's how I ruled it out.)
2. **Adminer refusing to log in.** The local Postgres has one role, `admin`,
   from the root `.env`; I was typing `crescent`, which is the `.env.example`
   placeholder.
3. **A test suite that hit Brevo for real.** The real API key in `.env` was
   being picked up during tests. `conftest.py` now blanks the email credentials
   so the suite can never reach the network, and tests monkeypatch `send_invite`
   to capture the token instead.
4. **macOS `sed` and `\b`** — see above.

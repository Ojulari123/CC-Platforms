## The boss's ask (verbatim)

> "Tie them to the repo's not necessarily the team.
> By default they should be a Team Lead, and deputy team lead at all times."

## What it means (confirmed with the intern)

- The **repository is the unit of work.** Engineers are grouped by the repos they
  work on; the repo is what a report is *about*. Engineers "don't matter" beyond
  *who made the change* and *who owns the report*.
- **One report per engineer, per repo, per week.** Ada works on repo A and repo B
  → **two** reports: one to repo A's lead, one to repo B's lead.
- Every repo has a **lead + deputy at all times**, and **both can approve** its
  reports (co-approvers) — because the system can't reliably detect when a lead is
  "away".
- Leadership is **per repo**: one person can lead/deputise several repos, and
  engineers can be on several repos.

## Decisions (confirmed 2026-07-30)

- **Pulse owns the repo-centric structure** (repo → lead, deputy, dept,
  membership), all by identity `user_id`. Rationale: repos are Pulse's data
  (synced from GitHub); Identity must never learn about GitHub. Identity stays
  lean (people, roles, auth). The token `leads` claim is no longer used for
  approval routing — Pulse reads its own tables.
- **Repos replace teams for reporting.** Identity's team model is left **parked**
  (built + tested), unused by the new flow. The boss is set on repos, not teams;
  a "how to delete teams" runbook is recorded in the decision doc for when that's
  requested explicitly.
- **Membership derived from GitHub activity**; **repos belong to a department**;
  **lead + deputy both approve** (co-approvers, no "away" detection); **either a
  dept admin or platform admin assigns** lead/deputy/dept; **a repo with no
  lead/deputy doesn't block reports** — they wait in `submitted`. Enforce
  **lead ≠ deputy** and never leave a repo without either.

Full detail + schema impact: `docs/decisions/2026-07-30-repo-centric-reporting.md`.

## Behavior changes to know (end-of-Week-3 review fixes)

- **`POST /github/sync` default changed from inline to queued.** It now enqueues
  the Celery task (needs the worker running) and returns a `task_id`. To run one
  pass **inline** and get the per-repo results straight back (e.g. a demo), use
  **`POST /github/sync?wait=true`**.
- **Report creation now requires synced activity.** An engineer can only open a
  report for a repo they have attributed GitHub activity in (a repo's lead/deputy
  and admins bypass). No activity → a clear 403 telling them to connect + sync.

## Post-review fixes (appended after a full Week-3 codebase review)

A full read of the codebase against the internship plan turned up one real defect
and a workflow gap. Both fixed in Pulse, with tests; **suite 102 → 113 green**,
no schema/migration change.

- **Report `dept_id` no longer goes stale.** A report's `dept_id` is a
  denormalised copy of its repo's department, taken at creation for fast
  department-admin visibility. But Decision 7 lets an engineer open a report on a
  repo *before* it's filed under a department — so those reports were stranded at
  `dept_id = NULL` and stayed invisible to the department admin forever (and never
  showed in `GET /reports?dept_id=…`). `set_department` now re-stamps every report
  on the repo, so reports follow the repo into — or between — departments.
  Contradicted Decision 3 ("a dept admin sees every report across their dept's
  repos") until now. (`app/services/repositories.py`.)
- **Approver's inbox — `GET /reports/review-queue`.** `list_reports` only widened
  past "your own" when you named a `repo_id`, so a lead of several repos had no
  single "what's waiting on me" call. The new endpoint returns `submitted` reports
  (overridable via `?status=`) across every repo the caller leads/deputises; a
  department admin gets their department's repos, a platform admin gets
  everything. This is the backend the Week-4 approval UI will hang off.
  (`app/services/reports.py`, `app/routes/reports.py`.)

**Reviewed and deliberately left as-is:** GitHub webhooks (deferred — daily sync
already meets "syncs on a schedule"); `GITHUB_ORG` config unused for now (kept on
purpose — it's for the CypherCrescent-org rollout; personal-account testing only
uses the `GITHUB_REPOS` allowlist); OAuth scope `read:user` (fine for public
repos; will need `repo` scope for private org repos later); `celerybeat-schedule`
committed (minor hygiene). All recorded so they aren't silently forgotten.

### 2. Ported security → RS256
Split FindYourCribb's `Utils/security.py` into three files under `services/identity/app/security/`:
- [password.py](services/identity/app/security/password.py) — `hash_password` / `verify_password` / `validate_password` (bcrypt, unchanged from source).
- [keys.py](services/identity/app/security/keys.py) — loads RSA PEM files, converts the public key to a JWK, and derives a stable `kid` from `sha256(public_key_pem)[:16]` so the same input always produces the same key id.
- [jwt.py](services/identity/app/security/jwt.py) — `create_access_token` / `decode_access_token`. Signs with the RSA **private** key, verifies with the **public** key, includes `kid` in the header so verifiers can pick the right key when we rotate.

Access-token claims: `sub` (user_id), `email`, `org_id`, `role`, `tv` (token_version), `token_type: "access"`, `iss`, `iat`, `exp`, `jti`.

### 3. Models
Single file at [app/models/__init__.py](services/identity/app/models/__init__.py), SQLAlchemy 2.0 style. Portable across Postgres (prod) and SQLite (tests) — no dialect-specific types.

- `User` — email/password_hash/name/avatar/`token_version` (bump to kill all outstanding access tokens).
- `Org` — id + slug (unique).
- `Team` — belongs to an org; `UniqueConstraint(org_id, slug)`.
- `Membership` — user ↔ org (+ optional team) + role. `UniqueConstraint(user_id, org_id)`. **Schema is multi-org-ready** even though we only issue one per user for now.
- `RefreshToken` — stores `token_hash` (SHA-256 of the raw token), `family_id`, `expires_at`, `is_revoked`, `replaced_by`. Direct port of FindYourCribb's family + rotation pattern.

## Decisions (this session)
| Decision | Value | Why |
|---|---|---|
| Refresh token format | Opaque random string (`secrets.token_urlsafe(64)`), stored as SHA-256 hash | FindYourCribb pattern; a DB dump doesn't leak usable tokens |
| Refresh rotation family | 32-byte URL-safe `family_id` per login, propagated on rotation | Enables stolen-token detection (nuke-family on reuse) |
| Access-token claims | `sub, email, org_id, role, tv, token_type, iss, iat, exp, jti` | Enough for products to decide permissions locally without touching identity's DB |
| `kid` derivation | First 16 hex chars of `sha256(public_key_pem)` | Deterministic across restarts, changes only when key rotates |
| Register flow | Creates user + new org + owner-role membership atomically | Self-signup founder flow — simplest working shape until we design admin-invite |
| Logout | Idempotent (204 even on unknown token) | Callers shouldn't have to try/catch to log out cleanly |
| Test DB | SQLite in-memory + `StaticPool` | No Postgres container needed for `pytest` — fast local loop |
| Test keys | Fresh 2048-bit RSA keypair generated in `conftest.py` before any app import | Tests don't depend on committed dev keys or environment |
| Docker reload scope | `--reload-dir app` (not the whole `/app` mount) | Prevents host `.venv` from causing reload loops |

**B) No Docker (identity only, needs Postgres somewhere)**
```bash
cd services/identity
python3.14 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt

../../scripts/generate-identity-keys.sh   # from repo root
cp .env.example .env
# edit DATABASE_URL if your Postgres isn't at the default

alembic upgrade head
uvicorn app.main:app --reload --port 8001

# and to run tests (no DB needed — uses SQLite in-memory):
pytest
```

### Built `packages/core/` — the shared token verifier
First real code in the shared package. Pulse and Forge will consume this instead of copying JWT-verify logic or (worse) touching identity's DB.

Layout:
```
packages/core/
├── pyproject.toml            (installable — pip install -e ../../packages/core)
├── README.md
├── crescent_core/
│   ├── __init__.py           (re-exports the public API)
│   ├── claims.py             (TokenClaims dataclass)
│   ├── jwks.py               (JWKSClient: TTL cache + refresh-on-unknown-kid + injectable fetcher)
│   ├── verify.py             (verify_access_token: sig + expiry + issuer + token_type checks)
│   └── deps.py               (current_user_dep + require_role factories for FastAPI)
└── tests/
    ├── conftest.py           (ephemeral RSA keypair; fake JWKS; sign_token helper)
    ├── test_jwks.py
    ├── test_verify.py
    └── test_deps.py
```

**Design highlights:**
- **Injectable `fetcher`** on `JWKSClient` — tests supply a lambda returning the JWKS dict directly; no `httpx` mocking library needed.
- **Refresh-on-unknown-kid** — supports key rotation without needing a full restart or TTL expiry.
- **No dependency on identity** — talks to identity over HTTP only, never imports anything from `services/identity/`.
- **`require_role` factory** — Pulse can do `manager_only = require_role("manager", "owner")` and gate endpoints with it.
